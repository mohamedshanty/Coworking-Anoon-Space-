# noonWiFi — ربط noonCowork + Anoon QR بـ MikroTik RouterOS v6.49.19

حزمة تنفيذ كاملة: بوابة أسر (Captive Portal) تظهر تلقائياً عند الاتصال بالشبكة، تسجّل المستخدم في
مساحة العمل، وتفرض سرعة الإنترنت وسعرها حسب نوع الشخص.

---

## 1. القرار المعماري الأهم

نسختك **v6.49.19 لا تملك REST API** (بدأ من v7.1). لكن التحقق أثبت أن الأمر
`/ip hotspot active login` موجود منذ v6.34 ويقبل `user`, `password`, `ip`, `mac-address`.

هذا يعني أننا **لا نحتاج المتصفح ليرسل نموذج تسجيل الدخول للراوتر إطلاقاً**. الخادم هو من يسجّل
دخول الجهاز. الفائدة:

- لا مشكلة `mixed content` (بوابة HTTPS ترسل POST لـ `http://10.10.0.1/login` — كانت ستُحظر).
- لا حاجة لتعطيل CHAP أو التعامل مع `chap-challenge` و `md5.js`.
- كل المنطق في مكان واحد يمكن اختباره وتسجيل أخطائه.

الاتصال بالراوتر يتم عبر **Binary API على المنفذ 8728** باستخدام مكتبة `node-routeros`.

### أين يعيش الكود؟

| المكوّن | المكان | السبب |
|---|---|---|
| وحدة Hotspot + عميل MikroTik | **noonCowork backend** (Hostinger VPS) | مصدر الحقيقة للمشتركين، لا cold start، ويستطيع حمل نفق VPN دائم للراوتر |
| صفحة البوابة (Portal) | تُخدَّم static من نفس الـ VPS تحت `/portal` | نفس الأصل مع الـ API، بدون cold start — البوابة يجب أن تفتح خلال ثانيتين وإلا يفشل كاشف الـ captive portal في الهاتف |
| Anoon QR | يبقى كما هو | يستقبل حضور المشتركين (fire-and-forget) وتنبيهات Telegram |

> **لماذا ليس Render؟** الخطة المجانية تدخل في سبات، وأول طلب يستغرق ~50 ثانية. كاشف
> البوابة في iOS/Android ينتظر ثوانٍ قليلة فقط ثم يعتبر الشبكة بلا إنترنت.

## 2. التدفق الكامل

```
1. الجهاز يتصل بشبكة NOON-WIFI  →  DHCP  →  الـ Hotspot يعترض
2. الراوتر يعرض login.html  →  إعادة توجيه إلى:
   https://<VPS>/portal?mac=..&ip=..&link-orig=..
3. البوابة تنادي  GET /api/v1/hotspot/context?mac=..
      ← هل الجهاز معروف؟ ← ما اسم صاحبه ونوعه؟ ← ما الباقات المتاحة؟
4. المستخدم يدخل الاسم + الجوال (أول مرة فقط) ويختار السرعة (للزوار فقط)
5. POST /api/v1/hotspot/login   →  الخادم ينفّذ بالترتيب:
      أ) resolveIdentity(phone) → SUBSCRIBER | TRAINEE | EMPLOYEE | VISITOR
      ب) اختيار الـ profile:  غير الزائر ⇒ noon-10m  |  الزائر ⇒ tier المختار
      ج) ensureHotspotUser على الراوتر (اسم المستخدم = رقم الجوال)
      د) /ip hotspot active login  للجهاز الحالي
      هـ) إنشاء/جلب جلسة الحضور في noonCowork (نفس SessionsService الحالي)
      و) حفظ KnownDevice(mac ↔ phone) + NetSession
      ز) إعادة تفويض كل أجهزة نفس الرقم المعروفة (لابتوب/تابلت) عبر DHCP lease
      ح) إشعار Anoon QR بالحضور (fire-and-forget)
6. شاشة نجاح: الاسم، السرعة، السعر/ساعة، ثم تحويل إلى link-orig
7. الخروج: زر "إنهاء الجلسة" في صفحة «داخل المساحة»
      → إنهاء NetSession + حساب الفاتورة + /ip hotspot active remove + تعطيل المستخدم
8. شبكة أمان: كرون نهاية الدوام يقطع كل الزوار + scheduler على الراوتر نفسه
```

## 3. التسعير

| النوع | السرعة | السعر |
|---|---|---|
| زائر — باقة 10 | 10M/10M | 3 شيكل/ساعة |
| زائر — باقة 20 | 20M/20M | 4 شيكل/ساعة |
| زائر — باقة 30 | 30M/30M | 5 شيكل/ساعة |
| مشترك | 10M/10M | مجاني (ضمن الاشتراك) |
| متدرّب | 10M/10M | مجاني (ضمن الدورة) |
| موظف | 10M/10M | مجاني |

كل القيم في `HOTSPOT_PLANS` داخل `hotspot.config.ts` — تُعدَّل من مكان واحد بدون لمس المنطق.

**التقريب الافتراضي:** حد أدنى 60 دقيقة، ثم كل 15 دقيقة تُقرَّب لأعلى.
(`BILLING_MIN_MINUTES=60`, `BILLING_INCREMENT_MINUTES=15`)

## 4. قراران يحتاجان تأكيدك قبل التشغيل

**(أ) هل الـ 3/4/5 شيكل هي سعر الساعة الكامل أم إضافة على سعر المقعد؟**
noonCowork يحاسب الزائر بالساعة أصلاً. الكود يدعم الوضعين عبر متغيّر واحد:

```
INTERNET_BILLING_MODE=surcharge   # يُضاف فوق سعر الساعة الحالي  (الافتراضي)
INTERNET_BILLING_MODE=replaces    # يحل محل سعر الساعة الحالي للزائر
```

**(ب) كيف يصل الـ VPS إلى الراوتر؟** الراوتر داخل المساحة خلف NAT غالباً، والـ API لا يعمل عبر
الإنترنت مباشرة. الخيارات مرتّبة بالأفضلية:

1. **نفق L2TP/IPsec** — الراوتر يتصل بالـ VPS كعميل، ويحصل على `10.20.0.2` ثابت.
   ملف `mikrotik/03-l2tp-client.rsc` جاهز. **هذا هو الموصى به** (WireGuard غير مدعوم في v6).
2. IP ثابت في المساحة + `/ip service set api address=<VPS_IP>` + جدار ناري.
   يعمل لكنه يعرّض 8728 (نص صريح) للإنترنت — استخدم `api-ssl` 8729 لو اخترته.

## 6. الأمان — ما هو مغطّى

- مسارات البوابة عامة (لا يمكن غير ذلك) لكنها **مقيّدة بالـ MAC/IP القادمين من الـ hotspot**:
  الخادم يتحقق أن الـ MAC موجود فعلاً في `/ip hotspot host` قبل أي تفويض. لا يستطيع أحد من
  خارج الشبكة تفويض جهاز.
- Rate limit 20 طلب/دقيقة لكل MAC.
- كلمة سر مستخدم الـ hotspot تُولَّد عشوائياً وتُخزَّن hash فقط عندنا (الراوتر يحفظ نسخته).
- مستخدم API على الراوتر بصلاحيات `api,read,write,test` فقط ومقيّد بعنوان الـ VPS.
- **الـ mac-cookie معطّل عمداً** — وإلا لتذكّر الراوتر الجهاز ودخل تلقائياً بدون مسح الـ QR،
  وهو ما ينسف الهدف الأساسي من المشروع.
